# 知枢 · 可观测模块与评测集模块设计

> 版本：v1.0（2026-10-29）  
> 目标：把「黑盒对话」升级为「可回放的执行链路」，并把线上真实 Case 沉淀为可运营的评测资产。

---

## 一、设计原则

1. **一次调用 = 一条 Trace，一步执行 = 一个 Span。** 所有观测维度（耗时、Token、成本、异常、上下文）都挂在这棵树上，不再散落在 ChatLog / ToolCallLog 里。
2. **观测即产品，不是运维附件。** 产品、运营、算法、研发用同一套链路数据：看效果（对话日志）、看成本（计费）、看质量（异常/坏例）、看知识（构建过程）。
3. **ReAct 全量留痕，不做"结果截断"。** Thought / Action / Observation / Final 原文、工具入参出参、模型原始返回、上下文消息全部保留；长文本只在列表页压缩，详情页可展开原文。
4. **代码级可解释。** 每个节点不仅是 I/O，还附带"这段内部实现怎么跑的"代码快照 + 逐段中文解释，满足"单节点可展开查看内部运行代码"的要求。
5. **Case 回流是低摩擦动作。** 在日志、链路详情、评测集任何位置，一键标记 good / bad 并归入评测集；不要求先建表、填表单。

---

## 二、观测对象与指标

| 观测面 | Trace 类型 | 关键 Span | 核心指标 |
|---|---|---|---|
| 知识库构建 | `kb_build` | 解析、OCR、分块、Embedding、向量入库 | 阶段耗时、分块数、Token、失败原因、策略/模型 |
| 简易 RAG 对话 | `chat` | 检索（embedding/召回/rerank）、上下文组装、LLM、回答 | 召回分数、引用、首字/总耗时、Token、成本 |
| Chat Flow | `chatflow` | 各节点（检索/LLM/工具/条件/输出） | 节点耗时、分支走向、变量快照、异常 |
| Agent | `agent` | Plan、Thought、Action、Tool、Skill、Observation、Final | ReAct 轮次、工具/Skill 成败、单步 Token、上下文、异常 |
| 对话日志 | 以上全部 | — | 用户/应用/知识库/状态/时长 |
| 计费消耗 | 以上全部 | 按 span 聚合 | 输入/输出 Token、按模型/应用/用途成本、日趋势 |

### Agent 观测必填项（对齐需求）

- **单次输入输出内容**：用户输入、系统提示词、拼接后的上下文、每一轮模型原始输出、最终回答。
- **运行状态**：trace 状态（running/success/error/degraded）+ 每步状态（success/error/skipped）。
- **工具调用状态**：工具名、参数、结果、耗时、错误、调用序号。
- **Skill 调用**：Skill 名、入参、结果、耗时；与 Tool 区分展示（内置能力 vs 注册工具）。
- **单次 Token 消耗**：每轮 Thought 的 input/output tokens，以及 trace 汇总。
- **调用上下文**：系统提示词、历史消息、检索分块（含分数/来源）、可用工具与 Skill 清单、应用配置。
- **Harness 相关异常**：LLM 超时/限流、工具异常、Skill 参数错误、循环上限、上下文超长、解析/Embedding 失败，统一落 `exception` span 并给出可读原因。

## 三、数据模型

### 3.1 `trace_runs`（一次执行）

| 字段 | 说明 |
|---|---|
| `id` | trace id（32 位） |
| `trace_type` | `chat` / `chatflow` / `agent` / `kb_build` |
| `title` / `query` | 列表标题、用户原始输入 |
| `answer` | 最终输出 |
| `status` | `running` / `success` / `error` |
| `app_id` / `app_name` / `app_kind` | 来源应用 |
| `kb_id` / `kb_name` | 来源知识库（构建场景为被构建库） |
| `conversation_id` / `message_id` | 关联会话与助手消息 |
| `role` / `source` | 角色、internal/public |
| `model` / `models` | 主模型、各用途模型 |
| `tokens` | `{input, output, total, embedding, rerank, llm}` |
| `cost_cny` | 本次总成本（元） |
| `duration_ms` | 总耗时 |
| `started_at` | 开始时间（可按天聚合） |
| `span_count` | 节点数 |
| `context` | 系统提示词、历史消息、检索分块、应用配置、可用工具/Skill |
| `error` | 失败摘要 |
| `metadata` | 文档 id、是否演示数据等扩展 |

### 3.2 `trace_spans`（一步执行）

| 字段 | 说明 |
|---|---|
| `id` / `trace_id` / `parent_id` | 树结构 |
| `seq` / `depth` | 展示顺序与层级 |
| `span_type` | `react.plan` / `react.thought` / `react.action` / `tool.call` / `skill.call` / `react.observation` / `retrieval.embed` / `retrieval.search` / `retrieval.rerank` / `context.assemble` / `llm.call` / `flow.node` / `build.parse` / `build.chunk` / `build.embed` / `build.index` / `final.answer` / `exception` |
| `name` | 展示名（如「第 2 轮 · 调用 导出 Word」） |
| `status` | `success` / `error` / `skipped` |
| `duration_ms` / `started_offset_ms` | 耗时与相对起点 |
| `input` / `output` | 全量 JSON 或文本（仅存储上限保护） |
| `tokens` / `cost_cny` | 该步消耗 |
| `context` | 该步上下文（消息数、可用工具、检索参数等） |
| `error` / `error_hint` | 异常原文与可读建议 |
| `code_key` / `code` / `code_explain` | 代码快照与逐段解释 |
| `metadata` | 轮次、节点 id、工具类型等 |

### 3.3 `model_prices`（计费）

`model`、`input_price`（元/百万 Token）、`output_price`、`currency`、`updated_at`。内置通义 / OpenAI 兼容常见模型价格，未知模型走默认单价；支持后台修改。

### 3.4 `eval_cases`（Case 池）

`question`、`answer`、`reference_answer`、`contexts`、`label`（good/bad）、`status`（candidate/confirmed）、`app_id/name`、`source`（trace/log/manual）、`trace_id`、`tags`、`note`、`created_by`、时间。同一 trace 重复回流时更新已有 Case，避免重复。

### 3.5 `eval_sets` + `eval_set_items`（评测集）

评测集是 Case 的显式聚合，支持 good / bad 混合、手动挑选、随时增删、JSONL 导出。列表返回 Case 数、good/bad 分布、最近更新时间。

## 四、埋点方案

### 4.1 Agent（重点）

```
Trace(agent)
├─ retrieval.embed / search / rerank     # 入口检索（如绑定知识库）
├─ react.plan                            # 系统提示词、可用工具/Skill、上下文规模
├─ round 1
│  ├─ react.thought                      # 模型原始输出（content / reasoning / tool_calls）
│  ├─ react.action                       # 决策：调用哪个工具/Skill，参数原文
│  ├─ tool.call | skill.call             # 执行结果、耗时、状态、错误
│  └─ react.observation                  # 回填给模型的内容
├─ round 2 …
├─ exception                             # 工具/Skill/LLM 异常（如有）
└─ final.answer                          # 最终回答
```

- 每轮 `thought` 记录 `usage_metadata` → 单步 Token / 成本。
- 工具异常不吞：`execute_tool` 返回的错误文本会同时标记 `error` 并生成 `exception` span。
- 达到最大循环（5）时记录 `exception` + `final.answer`（总结回答），trace 标 `degraded`。
- Skill 内置：知识库检索、数据计算；系统工具（导出 Word / 联网搜索）也按 Skill 归类展示；HTTP 工具按 Tool 展示。

### 4.2 简易 RAG / Chat Flow / 构建

- 简易 RAG：检索三步（embedding、向量召回、rerank 降级原因）→ 上下文组装（system/history/contexts）→ 流式 LLM → 回答。
- Chat Flow：每个节点一个 `flow.node` span，带节点 id、类型、变量快照与分支结果；LLM 节点带 Token，工具节点带结果。
- 构建：解析（含 OCR 警告）→ 分块（策略、数量、样例）→ Embedding（模型、批次数、Token）→ 入库（chunk 数、维度）；失败打 `exception` 并结束 trace。

### 4.3 与现有数据的衔接

- `chat_logs` 增加 `trace_id`（启动时 `ADD COLUMN IF NOT EXISTS` 兼容已有库）。
- 对话完成 SSE `done` 事件返回 `trace_id`，前端回答气泡可直达链路详情。
- 旧日志无 trace 时，仍支持以日志中的 question/answer 手动回流 Case。

## 五、页面设计

### 5.1 可观测中心 `/app/observability`

- 顶部：时间范围（今日/7 天/14 天）、刷新、载入演示数据。
- KPI：调用量、成功率、P95 耗时、Token、成本（¥）。
- 趋势图：调用量/错误量折线 + 成本柱状（自绘 SVG，保持项目零图表依赖）。
- Tabs：
  1. **调用链**：类型/状态/应用/关键词筛选；表格展示时间、类型、应用、输入、状态、步数、Token、成本、耗时；行内「查看链路」「回流」。
  2. **对话日志**：沿用日志表，新增 trace 入口与一键回流。
  3. **计费消耗**：日成本趋势、按模型/应用/用途明细、单价配置。
  4. **知识库构建**：构建任务列表 + 阶段耗时条，点击展开阶段详情。

### 5.2 链路详情 `/app/observability/traces/:id`

- 顶部：状态、应用、trace id、总耗时、Token、成本、回流按钮。
- 左栏「执行链路」：
  - 水平链路缩略图（节点 + 连线 + 状态色），点击定位到节点。
  - 纵向 ReAct 时间线：Plan / Round（Thought → Action → Tool/Skill → Observation）/ Final，每张卡片可展开。
  - 展开后四个 Tab：**输入**、**输出**、**上下文**、**运行代码**。
  - 代码 Tab：带行号代码 + 逐段中文解释（这段在做什么、为什么这么设计、失败了会怎样）。
  - 异常节点红色高亮，展开显示 error + hint。
- 右栏「概览 / 上下文 / 异常」：应用配置、模型、系统提示词、历史消息、检索分块、可用工具/Skill、关联 Case。

### 5.3 评测集 `/app/eval`

- 顶部 KPI：Case 总数、Good、Bad、评测集数、本周新增。
- Tab「Case 池」：
  - 筛选：标签、来源、应用、关键词；多选批量「加入评测集」。
  - 列表：问题、标签、应用、来源、时间、备注；行内查看/编辑/删除。
  - 手工回流：填写问题、期望回答、标签、备注。
- Tab「评测集」：
  - 卡片列表：名称、Case 数、good/bad、更新时间；新建/编辑/删除。
  - 详情 `/app/eval/:id`：Case 表（可按标签筛选）、移出、继续添加、导出 JSONL、覆盖度统计。

### 5.4 回流入口

- 日志行「回流」、链路详情「标记 Good/Bad」、评测集详情「添加 Case」共用一个回流弹窗。
- 回流成功后 Toast 提示，并可直接跳转对应评测集。

## 七、验收标准

1. Agent 一次调用可在详情中看到 Plan、每轮 Thought/Action/Tool/Skill/Observation、Final 原文，单步 Token 与总成本可核对。
2. 工具失败、循环超限、LLM 异常均有红色异常节点和可读原因。
3. 任意节点可展开「运行代码」，代码带行号与中文逐段解释。
4. 知识库构建能看到解析→分块→Embedding→入库各阶段耗时、Token、失败原因。
5. 日志/链路可一键回流 good/bad Case，评测集可聚合、筛选、导出。
6. 计费按模型/应用/用途可拆解，单价可配置。
7. 旧数据不丢：无 trace 的历史日志仍可回流；`chat_logs` 平滑加列。
