# 知枢 · AI 应用中台 —— 产品落地路线图

> 依据《知枢-前端原型(1).html》梳理。当前工作区 `rag_hub` 已包含上一版「企业知识库中台」的完整代码（RAG 对话、三类型应用、模型配置、日志、容器化部署），本路线图在其基础上向「知枢」演进。

## 一、产品全景（原型拆解）

| 模块 | 原型内容 | 说明 |
|---|---|---|
| **工作台**（业务门户） | 业务场景分类（报告撰写/智能客服/制度审校/营销/办公提效）、应用卡片（类型徽标/使用人数/开始使用）、我的收藏、最近使用、本月业务沉淀统计、AI 生成应用入口 | 业务人员的首页 |
| **应用** | 三类应用形态：**简易**（提示词+知识库+表单）、**Chat Flow**（可视化多步骤编排，分支/循环/人工确认）、**Agent**（自主规划调用工具）；状态机：草稿 → 评测中 → 已发布（带版本 vN）；编排/试用入口；7 天调用量、满意度 | 核心生产引擎 |
| **知识库** | 5 种类型：通用 / 问答对 / 表格 / 网站同步 / 飞书知识库；**9 种分块策略**（智能/标题层级/自定义分隔/固定长度/父子/语义/问答对拆分/按页/表格按行）；构建前预览；状态（可用/索引中/失败）；绑定 embedding 模型；显示被哪些应用引用；文档解析状态（含 OCR 未配置提示） | RAG 根基 |
| **工具** | 工具库（HTTP / MCP / 工作流插件 / 系统内置）、统一接入供应用复用、近 7 天调用统计、被引用应用 | 应用能力扩展 |
| **看板** | 业务数据统计（应用调用、覆盖员工、新增知识、节省工时） | 运营观测 |
| **模型** | 按用途分组：默认对话 / 推理（通义千问）/ 长文写作 / 视觉 / 图片理解 / 本地部署 / 重排 | 现仅 embedding/rerank/LLM 三类 |
| **设置** | 成员（企业 SSO：飞书/企业微信同步）、角色与权限、Agent 接入（官网嵌入/企业微信，访客会话）、审计日志 | 企业化 |
| **发布渠道** | 官网嵌入、企业微信（访客直接对话） | 应用触达 |

## 二、现状盘点（rag_hub 已有能力）

| 已有 ✅ | 对应原型 |
|---|---|
| 知识库 CRUD + 多格式导入（Word/PDF/md/图片/表格）+ 云端 OCR + 异步解析 + pgvector 检索 | 通用知识库的子集 |
| 分块（按标题层级 + 递归切分，2 种） | 9 种分块策略中的 2 种 |
| 应用：3 类型（问答/客服/报告）= 简易应用形态；应用级 SSE 对话、引用溯源、多库绑定 | 简易应用 |
| 模型服务商（OpenRouter/AIHubmix/通义）+ embedding/rerank/LLM + 连通性测试 | 模型配置子集 |
| 角色（管理员/知识库管理员/使用者，前端切换）+ 对话日志（Token/时长） | 角色权限、审计日志雏形 |
| Docker Compose 一键部署 + pytest 22 用例 | — |

## 三、Gap 分析（需新开发）

1. **工作台**：业务门户（分类/收藏/最近/统计/AI 生成入口）——全新
2. **应用引擎升级**：应用类型（简易/Chat Flow/Agent）、版本 + 发布状态机、可视化编排器、试用/开始使用、满意度统计——大面积新开发
3. **知识库升级**：+3 种类型（问答对/表格/网站同步/飞书）、+7 种分块策略、分块预览、状态机、embedding 绑定、应用引用关系——核心改造
4. **工具模块**：工具注册/调用/统计——全新
5. **看板**：统计接口 + 图表页——全新
6. **设置**：SSO 成员、角色权限体系（现为前端假角色）、Agent 接入、审计日志——全新
7. **模型分组**：按用途分组与默认策略——扩展

## 四、落地路线图（分阶段）

### Phase 0 — 基座整合（✅ 已完成 2026-10-28）
- [x] 项目更名知枢：导航/品牌/文案对齐原型（工作台/应用/知识库/工具/看板/设置）
- [x] 数据模型扩展：Application 增加 `app_kind`、`status`、`version`、`category`；KnowledgeBase 增加 `kb_type`、`chunk_strategy`、`status`、`embedding_ref`
- [x] 工作台（业务门户）：场景分类卡片、全部应用卡片（形态/状态徽标+7天调用）、我的收藏、最近使用、本月业务沉淀统计、**AI 描述生成应用（真实 LLM）**
- [x] 应用列表/详情改版：形态/状态/版本/分类 + 筛选；占位页（工具/看板/设置）
- [x] 测试：pytest 22/22、浏览器全流程自测、容器重建部署
- 交付：可运行的新骨架，旧功能不回归

### Phase 1 — 知识库引擎升级（✅ 已完成 2026-10-28）
- [x] 9 种分块策略引擎：智能 / 标题层级 / 自定义分隔 / 固定长度 / 父子 / 语义 / 问答对拆分 / 按页 / 表格按行
- [x] **分块构建前预览**：上传（不自动索引）→ 试切块（可切换策略对比）→ 确认入库 → 后台向量化
- [x] 知识库类型驱动默认策略（通用/问答对/表格；网站同步/飞书为占位提示）+ 知识库状态机（可用/索引中）
- [x] 知识库绑定 embedding 模型：索引与检索模型一致（多库应用自动取公共模型）
- [x] 前端知识库列表/详情改版（类型徽标/策略/embedding/状态/被引用应用）
- [x] 自测：pytest 27/27、真实 embedding 语义检索命中、浏览器全流程、容器重建部署
- 验收：9 种策略均可预览对比，检索效果可验证

### Phase 2 — 应用引擎升级（✅ 已完成 2026-10-28）
- [x] 应用类型：简易（已有）/ **Chat Flow 可视化编排器**（节点：开始/知识库检索/LLM 生成/HTTP 工具/条件分支/结束输出；拖拽、端口连线、条件双出口、节点配置抽屉、校验提示）；Agent（工具规划）保持占位，待 Phase 3 工具模块
- [x] 版本与发布：草稿/评测中/已发布（已有）+ **版本快照与回滚**（保存自动快照、版本历史、一键恢复）
- [x] Chat Flow 执行引擎：变量模板 `{{var}}` 插值、条件分支、HTTP 工具调用、流式输出、引用溯源、循环保护
- [x] 工作台（Phase 0 已交付）：应用分类卡片/收藏/最近使用/统计/AI 生成入口
- [x] 自测：pytest 35/35（新增 8 个流程用例）、浏览器实测（节点增删/连线/保存/版本/chatflow 对话真实检索引用）
- 验收：客服流程（检索→回答模板）跑通；工具节点通过 HTTP 调用（错误路径已验证，真实工具接入待 Phase 3 工具模块统一管理）

### Phase 3 — 工具与发布（生态闭环）
- [ ] 工具模块：HTTP / MCP / 工作流插件 / 系统内置（导出 Word、联网搜索）+ 调用统计

- [ ] 看板：统计接口 + 图表页

### Phase 4 — 企业化（规模化）
- [ ] 登录与 SSO（飞书/企业微信）替代前端假角色

- [ ] 审计日志升级（全操作留痕）
- [ ] Agent 接入管理（渠道/访客/限流）

## 五、开发节奏建议

每阶段按「数据模型 → 后端服务/API → 前端页面 → pytest + 浏览器自测 → 更新部署」执行，逐模块交付可运行增量。

**建议从 Phase 1（知识库引擎升级）开始**：它是后续所有应用类型的根基，且复用现有解析/OCR/向量化管道，ROI 最高。Phase 2 的 Chat Flow 编排器工作量大，放到知识库就绪后单独攻坚。
